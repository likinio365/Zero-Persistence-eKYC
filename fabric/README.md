# Fabric — Hyperledger Fabric Network

Single-org Fabric 2.5 network with etcdraft ordering, CouchDB state database, and TLS enabled on all services.

## Topology

| Component | Name | Port |
|-----------|------|------|
| Fabric CA | `ca.org1.example.com` | 7054 |
| Orderer (etcdraft) | `orderer.example.com` | 7050 |
| Peer | `peer0.org1.example.com` | 7051 |
| CouchDB | `couchdb` | 5984 |
| CLI | `fabric-cli` | — |

- **Channel**: `kycchannel`
- **Organization**: `Org1MSP`
- **Chaincode**: `kyccc`

## Quick start

```bash
# 1. Start the network (generates crypto, creates channel)
./fabric/scripts/network.sh up

# 2. Deploy the chaincode
CC_VERSION=1.0 CC_SEQUENCE=1 ./fabric/scripts/deploy-chaincode.sh
```

Or via the top-level helper which does both:

```bash
./scripts/start-network.sh
```

## Scripts

### `network.sh`

Manages the Fabric network lifecycle.

```bash
./fabric/scripts/network.sh generate   # generate crypto material + channel artifacts (idempotent)
./fabric/scripts/network.sh up         # generate → start services → create channel → join → anchor peers
./fabric/scripts/network.sh down       # stop containers (preserves volumes and crypto material)
./fabric/scripts/network.sh clean      # stop + remove volumes + delete all generated artifacts
```

| Env var | Default | Description |
|---------|---------|-------------|
| `FABRIC_CHANNEL` | `kycchannel` | Channel name |
| `FABRIC_BIN_PATH` | system `PATH` | Directory containing `cryptogen` / `configtxgen` binaries |
| `ORDERER_ADDRESS` | `orderer.example.com:7050` | Orderer endpoint |

Fabric binaries are resolved in order: system `PATH` → `FABRIC_BIN_PATH` → `hyperledger/fabric-tools:2.5` Docker image (pulled automatically if needed).

### `deploy-chaincode.sh`

Deploys or upgrades the KYC chaincode using the Fabric 2.x lifecycle.

```bash
# Fresh deploy
CC_VERSION=1.0 CC_SEQUENCE=1 ./fabric/scripts/deploy-chaincode.sh

# Upgrade
CC_VERSION=2.0 CC_SEQUENCE=2 ./fabric/scripts/deploy-chaincode.sh
```

Steps: vendor → package → install → approve (Org1MSP) → checkcommitreadiness → commit → verify. All steps are idempotent — re-running with the same version/sequence is safe.

**CaaS (Chaincode as a Service)**: the peer does not build the chaincode image. The image is built on the host (`docker build -t kyccc-service:1.0 chaincode/`) and the peer connects to it over gRPC on port 7052. The deployment script creates a manual CaaS package (a tar archive containing `metadata.json` + `code.tar.gz`) because Fabric 2.5's peer CLI has no `--type ccaas` flag.

| Env var | Default | Description |
|---------|---------|-------------|
| `FABRIC_CHAINCODE` | `kyccc` | Chaincode name |
| `CC_VERSION` | `1.0` | Chaincode version (increment on upgrade) |
| `CC_SEQUENCE` | `1` | Lifecycle sequence (must increment with each upgrade) |
| `FABRIC_CHANNEL` | `kycchannel` | Target channel |

## Key files

| File | Purpose |
|------|---------|
| `configtx.yaml` | Channel profiles (`KYCGenesis`, `KYCChannel`), org policies, orderer config |
| `crypto-config.yaml` | Topology for `cryptogen` — 1 orderer org, 1 peer org (1 peer, 1 user) |
| `crypto-config/` | Generated crypto material (keys + certs) — gitignored, regenerated by `network.sh generate` |
| `channel-artifacts/` | Generated genesis block + channel tx — gitignored, regenerated by `network.sh generate` |

## After `docker compose down -v`

Full teardown wipes crypto material and channel artifacts. To bring everything back:

```bash
./fabric/scripts/network.sh clean      # removes any leftover artifacts
./fabric/scripts/network.sh up         # regenerates everything + recreates channel
CC_VERSION=1.0 CC_SEQUENCE=1 ./fabric/scripts/deploy-chaincode.sh
```

Chaincode sequence resets to 1 on a fresh network — always start with `CC_SEQUENCE=1`.

## Known Issues

| Issue | Fix |
|-------|-----|
| Go 1.22 rejects ECDSA cert from `cryptogen` | Delete `fabric/crypto-config/` and re-run `cryptogen` — second run produces compatible keys |
| Stale Docker bind mount after regeneration | Restart peer/fabric-cli containers after deleting and regenerating `crypto-config/` |
| `channel_exists()` always false | Container name lookup uses `docker ps --filter "name=fabric-cli"` (substring match) — ensure no other containers match |
| etcdraft requires TLS | All three services (orderer, peer, fabric-cli) need TLS env vars and matching volume mounts in `docker-compose.yml` |
